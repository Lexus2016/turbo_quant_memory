## Проблема

За долгую сессию накапливается выстраданное понимание того, почему код именно такой. Затем контекст сжимается — и это исчезает. В следующей сессии агент перечитывает те же файлы, заново выводит те же выводы и выставляет вам счёт за те же токены.

`CLAUDE.md` не масштабируется дальше нескольких десятков строк и не умеет отвечать на вопрос *«что мы решили насчёт X и почему?»*.

**Turbo Quant Memory** — это MCP-сервер, который даёт агенту постоянное хранилище с поиском, куда тот пишет по ходу работы: решения, уроки, паттерны, передачи между сессиями, плюс компактный индекс вашего Markdown. Поиск возвращает карточки результатов примерно на 220 символов вместо целых документов; полное содержимое агент подгружает только тогда, когда карточки недостаточно.

## Почему именно этот

|                              | **Turbo Quant Memory**                     | mem0 / OpenMemory          | MCP-сервер `memory` |
| :--------------------------- | :----------------------------------------- | :------------------------- | :------------------ |
| Где лежат данные             | всегда на вашем диске                       | облако вендора или самохост | на вашем диске     |
| Данные покидают машину       | **никогда**                                 | да, если не самохост       | никогда             |
| Поиск                        | гибридный BM25 + вектор, слияние через RRF  | плотный вектор             | точный обход графа  |
| Что возвращает запрос        | компактные карточки, подгрузка по запросу   | полные воспоминания        | полные узлы         |
| Граф знаний                  | да — с жизненным циклом и линтингом          | нет                        | да                  |
| Неанглийское содержимое      | кириллица совпадает точно «из коробки»       | по-разному                 | —                   |
| Считает собственную экономию | **да — `server_info()`**                    | нет                        | нет                 |
| Цена                         | бесплатно, MIT                              | платные тарифы             | бесплатно           |

Никакого HTTP-клиента, никакой телеметрии, никаких «звонков домой». Проверьте сами — команда ничего не вернёт:

```bash
grep -rnE '^[[:space:]]*(import|from)[[:space:]]+(requests|httpx|aiohttp|urllib3)\b' src/
```

Ради точности, одно исключение: при первом запуске `fastembed` скачивает модель эмбеддингов (~0,22 ГБ) с Hugging Face. После этого сервер работает полностью офлайн. Ваши заметки, код и секреты не передаются никуда — в пакете просто нет кода, способного их отправить.

## Установка

### Поручите установку агенту

Вставьте это в Claude Code, Codex, Gemini CLI, Cursor или Antigravity:

> Установи и настрой MCP-сервер Turbo Quant Memory для этого рабочего пространства из
> https://github.com/Lexus2016/turbo_quant_memory — действуй по README, зарегистрируй
> сервер `tqmemory`, выполни `turbo-memory-mcp skill install`, проведи проверку
> работоспособности и проиндексируй этот проект.

`skill install` копирует инструкцию по эксплуатации во все каталоги навыков агентов на машине, так что каждая следующая сессия уже знает, как пользоваться памятью, без отдельных объяснений.

### Или установите вручную

```bash
uv tool install turbo-quant-memory
```

Затем зарегистрируйте сервер в своём клиенте:

```bash
claude mcp add --scope project tqmemory -- turbo-memory-mcp serve   # Claude Code
codex  mcp add tqmemory -- turbo-memory-mcp serve                   # Codex
gemini mcp add tqmemory turbo-memory-mcp serve                      # Gemini CLI
```

Cursor, OpenCode, Antigravity и другие клиенты → [CLIENT_INTEGRATIONS.ru.md](CLIENT_INTEGRATIONS.ru.md).
Hermes запускает MCP через systemd-шлюз → [docs/hermes.ru.md](docs/hermes.ru.md).

## Что он делает

* **Типизированные заметки.** `decision`, `lesson`, `pattern`, `handoff` — каждая хранится с тегами, происхождением и связью в графе знаний с файлом или задачей, которой касается.
* **Уровни памяти.** `durable` (решения, паттерны) и `reference` (проиндексированные документы) ищутся по умолчанию; `episodic` (передачи между сессиями) не мешает, пока вы его не запросите, так что вчерашний шум никогда не хоронит архитектурное решение.
* **Гибридный поиск.** Ведёт плотный векторный канал; канал BM25 спасает точные термины — имена функций, пути к файлам, идентификаторы — и сливается через Reciprocal Rank Fusion. Кириллица и другие неанглийские термины совпадают точно, без учёта регистра и диакритики, без каких-либо настроек.
* **Граф знаний.** Направленные связи с метками времени между заметками, файлами и задачами. Результаты поиска несут связанный контекст внутри, так что агенту не нужен второй запрос.
* **Заметки человека весят больше заметок агента.** Всё, что вы явно попросили запомнить, помечается как `human-explicit` и при равной релевантности стоит выше собственных наблюдений агента.
* **Зашифрованное хранилище секретов.** Привязано к проекту, AES-256-GCM, структурно недостижимо для поиска. → [docs/secrets-vault.ru.md](docs/secrets-vault.ru.md)
* **Работает на слабой машине.** Эмбеддер по умолчанию — ONNX через fastembed: без PyTorch, модель ~0,22 ГБ, комфортно на 2 ГБ оперативной памяти.

Полные технические подробности → [docs/features.ru.md](docs/features.ru.md)

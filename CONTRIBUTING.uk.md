# Участь у розробці Turbo Quant Memory

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md)

Потрібні Python 3.11+ та uv. Після клонування репозиторію виконайте перевірки з [CI](.github/workflows/ci.yml):

```bash
uv sync --frozen
uv run --no-sync ruff check src tests
uv run --no-sync mypy src/turbo_memory_mcp
uv run --no-sync pytest -q
```

Під час встановлення залежностей і моделей ембедингів може бути потрібна мережа. Для тестів використовуйте тимчасові дані, а не єдину копію робочого сховища пам’яті.

У звіті про помилку вкажіть версію пакета, ОС, Python, MCP-клієнт, мінімальні кроки відтворення та очищені діагностичні дані. Не публікуйте секрети, приватні нотатки, локальні бази чи облікові дані.

Робіть зміни невеликими й додавайте регресійні тести для нової поведінки. Зберігайте сумісність міграцій і межу між пам’яттю проєкту та глобальною. Перед зміною контрактів інструментів або встановлення прочитайте [AGENTS.md](AGENTS.md) та [інструкцію агента](src/turbo_memory_mcp/skills/turbo-quant-memory/SKILL.md).

Синхронізуйте користувацьку документацію англійською, українською й російською. README.md також використовується на PyPI: посилання на файли й зображення в ньому мають бути абсолютними. Не редагуйте вручну згенерований блок TQ-STATS і не подавайте його історичний приклад як поточний бенчмарк.

У pull request опишіть проблему, зміни, виконані команди та фактичні результати, включно з пропущеними чи заблокованими перевірками. Розрізняйте локальне сховище сервера й передавання даних MCP-клієнтом. [Ліцензія MIT](LICENSE) не змінюється.
